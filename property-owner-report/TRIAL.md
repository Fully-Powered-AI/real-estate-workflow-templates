# Property owner report: one trial on the invented example

- **Product:** Claude, run in Claude Code
- **Model:** Claude Sonnet 5.5 (model ID claude-sonnet-5-5)
- **Date:** 2026-11-10

This was one run of the capability template on its own invented example. The inputs are the invented data for Property X in `public/example.md` ("What the person supplies"); no client data was used. The run was made by a model that did not write the template. The inputs were read first and the example's published output was read only after the output below was produced. The text of the template's instruction block and output format was followed as written, without adding anything by hand.

## What was observed

- **Every required part was produced,** in the order of the output format. Nothing in the inputs made the template stop: the headers matched, no unit was repeated, every status was recognised, and the property and month agreed. No note named an eviction, a dispute or a tenant's personal circumstances.
- **All figures recomputed from the rows** and match the published example: 77.8% collection rate, 5,550.00 owed, 80.0% by units, 78.0% by area, ages of 72, 46, 18, 17 and 11 days, and the 200.00 difference between the statement and the collections report.
- **Differences from the published example are small.**
  - I put the roof-drain decision (N7) after the payment-plan decision (N6), in note order; the example has them the other way round. The template does not say how to order new decisions.
  - The example keeps "two showings of unit 106 in October, no application" in the body; I moved it to the gaps with the claim that 106 had been vacant since August, because step 6 says an assertion no record supports is not written into the body. This is a judgment call the template leaves open: showings are not a forecast, but no supplied record supports them.
  - The example links the owner's approval in N8 to WO-3112 in the maintenance section; I did not, because N8 does not give a work order number and matching by description is an inference.
  - I added that unit 109 received nothing in October, next to the manager's explanation. It is in the collections report; the note does not mention it.
  - Wording and punctuation differ.
- **Nothing in either output is missing from the inputs.** Every figure, date and name can be traced to a supplied row or note. The example's statement that the owner approved the heater replacement "on 2026-10-09" comes from N8's "9 October".
- **Where the instructions needed a guess.**
  - The order of "other open" work orders is not specified (I used oldest first).
  - The order of new decisions is not specified.
  - Whether a lease that is on notice (unit 104) belongs in "leases ending within the window": I listed it, marked as on notice.
  - Whether a claim about the past found only in a note, but harmless (the showings), goes to the body or the gaps.
  - Whether the closing count of "closed in the month" should say that closings after the summary's as-of date cannot be seen. It does not, and I left it to gap 1.
  - How to describe the example's unit 108 half-payment: the note says "half" but 1,000.00 of 2,050.00 is a little under half; I quoted the figures.
  - The "Prepared" line asks for each input "with its as-of date or period", but manager notes have none.
- **A defect the example did not exercise.** The collections report charged unit 105 1,500.00 while the tracker's Monthly Rent is 1,800.00 (a move-in on 5 October, so probably a part month). The template says Monthly Rent is not used, so nothing was flagged. That seems right for this report, but the template does not say whether to mention such a difference.
- **Limits of this trial.** One run, by one model, on one invented month with no stop conditions in it. The acceptance tests in the template (stale summary, header mismatch, asked to send and the others) were not run. Nothing here shows how the template behaves on a real client's exports. The template stays labelled as tried on an invented example, not tested for a client.

## Edits made after this run

Made on 10 November 2026 after an independent review, and not run again. The output and the observations above are as recorded and describe the template and the example as they stood at the run:

- **The pasted instructions** now carry rules that were only in the procedure: "not compared" when last month's report is missing, a Balance smaller than Charged minus Received shown as supplied with a gap, a payment arrangement recorded only as the note states it, a note naming a work order absent from the summary going to the gaps, unnumbered notes numbered in the order given, and a decision about lease terms, a purchase, a sale or a valuation listed as the manager worded it. They also list units on notice with their move-out date, in place of "notices dated in the month".
- **Points this run left open** are now settled in the template: new decisions in note order; open work orders oldest first within each list; a harmless claim about the past that no record supports, such as the showings, goes to the gaps; a note is linked to a work order only if it names the number; manager notes have no as-of date; a charged amount that differs from Monthly Rent is neither compared nor mentioned.
- **Rules moved into the pasted instructions** after the review, with no change to the procedure: a tracker status that a note contradicts goes to the gaps; the lease-end-passed line carries what the tracker and notes say about a renewal; the closing refusal also names a login code. The instructions were not run again.
- **Settled as the procedure already read:** the explanation is followed only by what the records show about the facts the note names, so the run's added remark that unit 109 received nothing, which the note does not mention, is not part of the template's output, and the example does not carry it. Closings after the work-order summary's as-of date cannot be seen; that is left to the staleness gap, as in this run.
- **The example** was changed to match: the two new decisions are in note order, the showings moved to gap 4, the link from N8 to WO-3112 was taken out, and note tags are numbered. The Open maintenance section of the example now also says the summary is more than the 5-day limit, so later changes are not shown.
